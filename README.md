# 🇯🇵 혼자보는 일본어 — 텔레그램 봇

1시간마다 생활 일본어 한 문장을 텔레그램으로 보내주는 봇입니다.
**말하기 연습이 목적**이라 일본어 글자 대신 **한글 발음**을 크게 보여주고, **발음 음성**도 함께 보냅니다.

Cloudflare Workers에서 서버리스로 동작하므로 **PC를 켜둘 필요가 없습니다.**

## 메시지 예시

```
🇯🇵 오늘의 한 문장

🗣 세키와 아리마스카

💬 자리 있나요?
📍 식당·카페 입구

💡 '세키'는 자리. 인원수는 손가락으로 표시하면 됩니다.

👉 소리 내서 3번 따라 해보세요.

📈 1/100문장 (1%) · 1회차
```

> 진도 표시는 처음에 막대 그래픽(`█░`, `🟩⬜`)을 썼지만 안드로이드 기본 폰트에서
> 깨져 보이는 경우가 있어 어떤 환경에서도 안전한 순수 텍스트로 바꿨습니다.

바로 뒤에 **발음 음성(mp3)** 이 이어서 전송됩니다.

## 특징

- **한글 발음 병기** — 일본어 문자를 몰라도 바로 따라 읽을 수 있음
- **발음 음성 첨부** — 원어민 발음을 듣고 따라하기 (별도 API 키 불필요)
- **중복 없는 순환 출제** — 100문장을 다 볼 때까지 같은 문장이 안 나옴
- **진도 영구 저장** — D1 데이터베이스에 기록되어 언제든 이어서 학습
- **조용한 시간** — 자는 동안(기본 0~7시)은 알림을 보내지 않음
- **24시간 자동 실행** — 외부 스케줄러가 매시 정각에 발송 엔드포인트를 호출
- **중복 발송 방지** — 같은 시간대에 여러 번 호출돼도 딱 한 번만 발송
- **밀린 문장 따라잡기** — 스케줄러가 멈춰도 봇에 말을 걸면 그 시점에 발송

## 명령어

| 명령어 | 설명 |
|--------|------|
| `/start` | 봇 시작 & 채팅 등록 |
| `/now` | 지금 바로 한 문장 받기 |
| `/again` | 진도와 상관없이 아무 문장 |
| `/stats` | 학습 진도 보기 |
| `/reset` | 진도 처음부터 다시 |
| `/stop` | 정기 발송 중지 |
| `/help` | 도움말 |

## 아키텍처

```
텔레그램 ──웹훅──▶ POST /webhook  → 명령어 즉시 응답
외부 스케줄러 ───▶ GET  /cron     → 정기 발송
(매시 정각)               │
                          ▼
                D1 (구독자 · 진도 · 발송슬롯)
```

일반 서버처럼 상시 실행되지 않고, **요청이 있을 때만 깨어나는** 방식이라
무료 한도 안에서 넉넉하게 동작합니다.

### 정기 발송은 왜 외부 스케줄러인가

Cloudflare Workers 자체에는 Cron 트리거가 있지만, **이 봇이 올라간
Workers for Platform 호스팅 환경은 Cron 트리거를 지원하지 않습니다.**
`wrangler.jsonc` 에 `triggers.crons` 를 넣어도 조용히 무시되어, 웹훅 명령어는
동작하는데 정기 발송만 안 되는 상태가 됩니다.

그래서 외부에서 매시간 `GET /cron` 을 호출하는 방식으로 처리합니다.
(`triggers.crons` 설정은 Cron을 지원하는 환경에 직접 배포할 경우를 위해
그대로 남겨두었습니다.)

중복 발송은 워커가 막습니다. `/cron` 은 먼저 현재 시간 슬롯
(`YYYY-MM-DD-HH`, KST 기준)을 `sent_slots` 테이블에 선점(`PRIMARY KEY`)하고,
이미 선점된 슬롯이면 발송을 건너뜁니다. 따라서 스케줄러가 재시도하거나 여러 곳에서
동시에 호출해도 **한 시간에 한 문장**이 보장됩니다.

```
1번째 호출 → {"ok":true,"slot":"2026-07-27-19","sent":1,"failed":0}
2번째 호출 → {"ok":true,"skipped":"already_sent","slot":"2026-07-27-19"}
조용한 시간 → {"ok":true,"skipped":"quiet_hours","hour":3}
```

#### `/cron` 은 왜 키가 없나

`/cron` 은 다른 관리 엔드포인트와 달리 `ADMIN_KEY` 를 요구하지 않습니다.
스케줄러 쪽에 비밀값을 등록하는 수동 설정 단계를 없애기 위한 선택이며,
다음 두 가지 때문에 안전합니다.

1. 시간 슬롯 선점 때문에 **한 시간에 최대 한 문장**만 나갑니다.
   외부에서 아무리 많이 호출해도 메시지 도배나 문장 조기 소모가 없습니다.
2. 응답에는 슬롯 정보와 발송 건수만 담기며, 학습 데이터나 토큰이 노출되지 않습니다.

`/status`, `/send` 등 상태를 읽거나 강제 발송하는 엔드포인트는 그대로
`ADMIN_KEY` 로 보호됩니다.

#### 스케줄러 붙이는 방법 (둘 중 하나)

**A. GitHub Actions** — `deploy/github-actions-hourly-send.yml` 을
`.github/workflows/hourly-send.yml` 로 복사해 커밋하면 끝입니다.
등록할 Secret 은 없습니다. 무료지만 실행 시각이 수 분~수십 분 밀릴 수 있고,
저장소가 60일간 활동이 없으면 자동 비활성화됩니다.

**B. 외부 크론 서비스** ([cron-job.org](https://cron-job.org) 등) —
`https://<워커주소>/cron` 을 등록하고 주기를 매시 정각으로 두면 됩니다.
정시성이 더 정확합니다.

### 스케줄러가 멈춰도 되는 안전망

스케줄러는 언제든 멈출 수 있습니다(GitHub Actions 자동 비활성화, 서비스 장애 등).
그래서 **봇에게 아무 메시지나 보내면** 이번 시간 몫이 아직 안 나갔는지 확인하고
밀려 있으면 바로 발송합니다.

- `/stats`, `/help` 처럼 문장을 주지 않는 명령 → 밀린 문장이 있으면 따라서 발송
- `/start`, `/now` → 이미 문장을 받았으므로 이번 시간 몫을 채운 것으로 처리
  (직후에 정기 발송이 겹쳐 오지 않음)
- 조용한 시간에는 따라잡기도 하지 않음

여기서도 슬롯 선점이 적용되므로 한 시간에 한 문장 규칙은 그대로 지켜집니다.

## 프로젝트 구조

```
├── src/
│   ├── index.js      # 웹훅 수신 + /cron 발송 + 관리 엔드포인트
│   ├── store.js      # D1 구독자·진도 관리
│   ├── telegram.js   # 텔레그램 Bot API 래퍼
│   ├── format.js     # 메시지 포맷팅
│   ├── tts.js        # 발음 음성 생성
│   └── phrases.js    # 문장 데이터 (자동 생성)
├── data/phrases.json # 문장 원본 100개
├── migrations/       # D1 스키마 (0001 초기, 0002 발송슬롯)
├── scripts/          # 문장 변환 스크립트
├── deploy/           # 외부 스케줄러 설정 예시
└── wrangler.jsonc    # Worker 설정
```

## 배포 방법

### 1. 봇 만들기
텔레그램 [@BotFather](https://t.me/BotFather) 에서 `/newbot` 으로 봇을 만들고 토큰을 받습니다.

### 2. 시크릿 설정
| 이름 | 설명 |
|------|------|
| `TELEGRAM_BOT_TOKEN` | BotFather에서 받은 토큰 |
| `WEBHOOK_SECRET` | 웹훅 위조 방지용 임의 문자열 |
| `ADMIN_KEY` | 관리 엔드포인트 접근용 임의 문자열 |

### 3. 배포 및 웹훅 등록
배포 후 아래 주소를 한 번 열면 웹훅이 등록됩니다.
```
https://<워커주소>/setup?key=<ADMIN_KEY>
```

### 4. 봇에게 /start
텔레그램에서 봇을 찾아 `/start` 를 보내면 등록 완료입니다.

### 5. 스케줄러 연결 (이걸 해야 정시에 옵니다)
위 [정기 발송은 왜 외부 스케줄러인가](#정기-발송은-왜-외부-스케줄러인가) 를 참고해
GitHub Actions 또는 외부 크론 서비스에 `https://<워커주소>/cron` 을 등록합니다.

이 단계를 빼먹어도 봇에 말을 걸면 밀린 문장이 따라오지만, **가만히 있어도 알아서
오게 하려면** 스케줄러를 붙여야 합니다.

## 관리 엔드포인트

아래 세 경로는 `?key=<ADMIN_KEY>` 가 필요합니다.

| 경로 | 설명 |
|------|------|
| `/setup` | 웹훅 등록 + 명령어 목록 등록 |
| `/status` | 봇·웹훅·구독자·진도 상태 조회 |
| `/send` | 즉시 발송 (조용한 시간·중복 방지 무시, 테스트용) |

`/cron` 은 스케줄러가 호출하는 경로로, 위와 달리 **키가 필요하지 않습니다.**
(이유는 [`/cron` 은 왜 키가 없나](#cron-은-왜-키가-없나) 참고)

## 설정 변경 (wrangler.jsonc 의 vars)

| 항목 | 기본값 | 설명 |
|------|--------|------|
| `INTERVAL_HOURS` | `1` | 안내 문구에 표시할 주기 |
| `TIMEZONE` | `Asia/Seoul` | 조용한 시간 판정 기준 |
| `QUIET_ENABLED` | `true` | 조용한 시간 사용 여부 |
| `QUIET_START_HOUR` | `0` | 조용한 시간 시작 |
| `QUIET_END_HOUR` | `7` | 조용한 시간 끝 |
| `SEND_VOICE` | `true` | 발음 음성 함께 보내기 |
| `SHOW_JAPANESE` | `false` | 일본어 원문 표시 |

> 실제 발송 주기는 **외부 스케줄러의 호출 주기**로 정해집니다.
> 예) 2시간마다 → 스케줄러 cron을 `"0 */2 * * *"` 로 변경.
> `INTERVAL_HOURS` 는 안내 문구 표시용일 뿐 실제 주기를 바꾸지 않습니다.

## 문장 추가하기

`data/phrases.json` 에 아래 형식으로 추가한 뒤 변환 스크립트를 실행합니다.

```json
{
  "jp": "ありがとうございます。",
  "kr_read": "아리가토- 고자이마스",
  "ko": "감사합니다.",
  "scene": "고마울 때 어디서나",
  "tip": "'토-'를 길게. 친구끼리는 '아리가토'만 해도 됩니다.",
  "level": 1
}
```

```bash
npm run build:phrases   # data/phrases.json → src/phrases.js
```

- `jp` 는 화면에 안 나와도 **음성 생성에 쓰이므로 반드시** 채워야 합니다.
- `kr_read` 의 `-` 는 장음(길게 늘이는 소리)을 뜻합니다.

## 로컬 개발

```bash
npm install
npm run db:local        # 로컬 D1 초기화 (migrations 전체 적용)
npm run dev             # 개발 서버

# 발송 테스트 (두 번 호출하면 두 번째는 already_sent)
curl "http://localhost:8787/cron"
```

`.dev.vars` 파일에 시크릿 3개를 넣으면 로컬에서도 실제 봇으로 테스트할 수 있습니다.

## 보안

- 토큰·시크릿은 Cloudflare Secret으로만 관리하며 저장소에 포함되지 않습니다.
- 웹훅은 `secret_token` 헤더를 검사해 위조 요청을 차단합니다.
- `/setup`·`/status`·`/send` 는 `ADMIN_KEY` 없이는 접근할 수 없습니다.
- `/cron` 은 공개지만 시간당 1회 제한과 정보 미노출로 악용 여지가 없습니다.
- `.env`, `.dev.vars`, `.secrets/` 는 `.gitignore` 처리되어 있습니다.
